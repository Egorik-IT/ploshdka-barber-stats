# Синхронизация справочников YCLIENTS

При запуске `npm run server` применяется идемпотентная миграция
`server/migrations/001_yclients_directory.sql`. Она добавляет таблицы кэша,
не изменяя существующие таблицы пользователей и сотрудников.

- `yclients_directory`: снимки клиентов, услуг и товаров. Ключ — филиал,
  тип справочника и внешний ID. `company_id` предотвращает показ старых
  клиентов после изменения привязки филиала.
- `yclients_directory_sync`: время последней успешной полной синхронизации.
- `yclients_client_details`: прежний кэш фотографий, больше не используется.
  Таблица сохранена для совместимости существующих баз.

Для клиентов используется GET `/clients/{company_id}`: этот метод помечен
в документации устаревшим, однако возвращает `comment`. Новый метод поиска
игнорирует это поле (проверено на реальной интеграции). Сохраняются только
поля, необходимые списку клиентов. Фото и история комментариев не загружаются; обычный комментарий карточки сохраняется.

`POST /api/branches/:id/sync` запускает фоновую задачу. Статус, текущий
справочник и число загруженных элементов возвращаются в `GET /api/branches`
как `syncJob`. Повторный запуск работающей задачи возвращает её статус.
Повторный запуск завершённой задачи доступен через минуту после старта.
Старый `POST /api/branches/:id/sync-staff` сохранён для совместимости.

Данные читаются через API YCLIENTS, с пагинацией для клиентов и товаров.
Общий клиент ограничивает частоту запросов в одном процессе. Снимок
справочников и сотрудники сохраняются в общей транзакции. При ошибке,
неполном ответе или повторяющейся странице обновление откатывается.
Строка филиала блокируется на время задачи: параллельная синхронизация
отклоняется. Просмотр закэшированных клиентов продолжает работать.

Статусы задач находятся в памяти текущего процесса Node.js. После его
перезапуска незавершённая транзакция откатывается, запуск нужно повторить.
Для нескольких экземпляров сервера потребуется общая очередь задач и
общий ограничитель запросов. Текущий вариант рассчитан на один сервер.

`GET /api/clients?branchId=1&page=1&search=...` возвращает по 50 клиентов
из локальной базы, без запросов к CRM. Доступ требует существующую сессию;
ограничений по ролям пока нет. Клиенты разных филиалов не объединяются
по телефону или имени. История посещений и статистика не входят в эти
справочники.

Проверки:

```powershell
node --test server/services/yclientsApi.test.js
$env:RUN_DB_TESTS='1'
node --test server/services/yclientsDirectory.integration.test.js
Remove-Item Env:RUN_DB_TESTS
```

Интеграционный тест использует настроенную PostgreSQL, создаёт тестовые
данные внутри транзакции и откатывает их. Запросы к YCLIENTS заменены
тестовыми ответами.

Контракты API сверены с https://developers.yclients.com/ru/.
