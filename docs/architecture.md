# Где искать логику приложения

Страницы собирают экран и загружают данные, компоненты отображают отдельные
блоки, серверные маршруты принимают запросы, сервисы работают с данными.
Общие формулы находятся в `shared`: сервер и браузер используют один код.
Классы для React-компонентов не нужны: разделение ответственности здесь
обеспечивается небольшими функциями и отдельными модулями.

## Расчёты и загрузка

Рейтинг «По проценту с услуг» сравнивает выручку сотрудника × его процент.
Почасовой минимум показан рядом для сравнения, но не меняет место в этом
рейтинге. Косметика в него не входит. Калькулятор в режиме «Максимум за
период» выбирает большую сумму: часы × ставка или выручка × процент.
Режим дневных максимумов оставлен отдельным: он может давать другой итог.

Обычный отчёт загружает данные выбранного периода. Для определения первого
визита, постоянных, потерянных и вернувшихся клиентов нужна более ранняя
история; её обработка вынесена в сервисы статистики и кэшируется. Поэтому
количество обработанных записей может превышать количество записей периода.
Список клиентов читается из локального справочника с пагинацией.

История в карточке запрашивается при раскрытии блока и кэшируется. Между
филиалами клиент сопоставляется по телефону в синхронизированных справочниках:
разные телефоны не объединяются, общий семейный телефон может объединить
визиты разных людей. Показываются состоявшиеся визиты.

На главной стоимость услуг и статус оплаты отображаются отдельно. При
частичной оплате точный остаток не вычисляется из стоимости услуг: для этого
нужны подтверждённые данные платежей YCLIENTS. Интерфейс предлагает проверить
остаток в YCLIENTS.

## Серверный доступ по ролям

Роль берётся из БД при каждом защищённом запросе (`authMiddleware.js`).
Общие проверки находятся в `server/middleware/roleAccess.js`.
Индивидуальные разрешения удалены из интерфейса и API. Старые записи в БД
сохранены, но приложение их не читает и не изменяет.

| Действие | Сотрудник | Администратор | Руководитель | Разработчик |
| --- | --- | --- | --- | --- |
| Своя статистика и калькулятор | Да | Да | Да | Да |
| Статистика других сотрудников | Нет | Без чужих ставок и заработка | Да | Да |
| Рейтинг | Нет | Без заработка | Да | Да |
| Финансы, настройки сети, изменение и синхронизация филиалов | Нет | Нет | Да | Да |
| Управление аккаунтами | Нет | Только сотрудниками | Сотрудниками и администраторами | Всеми, кроме системного developer |
| Предпросмотр другой роли | Нет | Нет | Нет | Да |

Сервер проверяет текущую и назначаемую роль при редактировании аккаунта.
Проверка целевого аккаунта при сохранении выполняется под блокировкой строки.
Руководитель не может редактировать другого руководителя или назначить эту
роль; это действие оставлено разработчику. Свой профиль отображается в настройках.

Сотрудники пока могут просматривать клиентов всех активных филиалов одной
сети согласно текущему сценарию приложения. Скрытые финансовые поля карточки,
произвольные дополнительные поля и суммы истории им не отправляются.
Фильтрация по организациям и отдельным разрешённым филиалам ещё не реализована.

При блокировке и смене пароля удаляются действующие сессии и отправляется
уведомление открытым вкладкам. Попытки входа ограничены на 15 минут:
10 на сочетание IP и логина, 100 на IP. Ограничитель хранится в памяти одного
процесса; перед несколькими экземплярами сервера нужно общее хранилище.

## Утверждённые ставки и пробный калькулятор

`calculation_settings` хранит три независимых вида настроек:
- `network` — базовые ставки категорий;
- `approved:<userId>` — утверждённые руководителем ставки сотрудника;
- `user:<userId>` — личные параметры только пробного калькулятора.

Утверждённые ставки редактируются в настройках руководителя, в блоке
«Утверждённые ставки сотрудников». API `PUT /api/settings/employees/:id`
проверяет роль manager/developer, категорию и значения на сервере.
Пустое значение наследует ставку категории, ноль остаётся нулём.
Старые личные параметры не перенесены в утверждённые автоматически.

Рейтинг, статистика заработка с косметики и калькулятор руководителя
используют итоговые утверждённые ставки из `calculationProfiles`.
Личный пробный калькулятор накладывает свои параметры на утверждённые.
Изменение чисел внутри карточки калькулятора ничего не сохраняет в ставках.
Уже открытые расчётные карточки сохраняют свои значения; новые ставки
подтягиваются при новой загрузке страницы. История ставок по датам пока
не ведётся: пересчёт прошлого периода использует текущие ставки.

## Что осталось после первого этапа защиты

- Изолировать организации и определить доступ администратора к филиалам.
- Настроить HTTPS, Secure cookie, доверенный reverse proxy, production origin
  и защиту изменяющих запросов от CSRF. Сейчас конфигурация рассчитана на localhost.
- Учёт расходов по операциям с датами, реальные времена обновления кэша,
  ограничение тяжёлых задач YCLIENTS и восстановление задач после перезапуска.
- Полные миграции для чистой БД, резервное копирование, журнал важных изменений.
- Подключение/отключение приложения через маркетплейс YCLIENTS.
- Проверить интерфейс отдельными аккаунтами каждой роли в браузере.

Текущий этап не означает готовность к публичному запуску. Тесты проверяют
отказ в прямых запросах API, иерархию, выдачу разрешённых полей и ограничение входа.

## Проверки

```powershell
npm run lint
npm run build
$env:RUN_DB_TESTS='1'
node --test shared/salary.test.js server/services/*.test.js
Remove-Item Env:RUN_DB_TESTS
```

Интеграционные тесты требуют настроенную PostgreSQL. Тестовые данные
создаются в транзакции и откатываются. Сборка и тесты не заменяют ручную
проверку внешнего вида в браузере.

## Графики отчётов

`ReportBarChart` — общий компонент полосовых диаграмм без дополнительных библиотек.
`ActivityChart` переключает визиты, неявки и количество услуг; до 45 дней
показывает дни, для более длинного периода суммирует данные по месяцам.
Серверный `reportCharts.dailyActivity` использует уже загруженные записи,
дополнительных запросов в YCLIENTS для графиков нет. Дни без записей показаны нулями.

Сотрудник видит динамику своих записей. Администратор и руководитель —
динамику выбранного сотрудника и первые 10 позиций выбранного рейтинга.
В финансах руководителя показаны выручка услуг по времени и суммарная
выручка услуг/косметики по филиалам. Графики не добавляют новых прав доступа.
Свободный ввод фактических выплат и расходов сохранён; эти суммы не
распределяются искусственно по дням и не подменяются расчётной зарплатой.
